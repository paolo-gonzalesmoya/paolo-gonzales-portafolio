# Fuente narrativa — Sistema integral de almacén TIMCO

## Relato original

“Mi proyecto consiste en el registro de las unidades que ingresan al almacén timco para ello se hace un registro inicial y un checklist que creará un PDF con los datos, el sistema crea un QR que al escanear el cliente puede ver su PDF de ingreso de la unidad. El sistema registra información como el tipo de unidad, area que ocupa, cliente, implementos de cada unidad, y también información respecto al combustible, estado limpio o sucio, Nuevo / Usado que luego se aprecia en el Layout de acuerdo a una leyenda de iconos. Con la información recaudada podemos identificar todas las unidades ingresadas, todas las que salieron y haciendo un cruce las que están en el inventario, los administradores jefes esperan ver las areas para saber cuánto cobrar, los almaceneros desean ver el layout para su control, cuando una unidad sale se compara el estado inicial y final para posibles reclamos con evidencias de fotos de todo, el pdf de salida tmb tiene su QR, el sistema permite manejar usuarios: admin, almacenero, cliente (observador) y ver el dash para calcular cobros. El layout puede mover tácticalmente o con el cursos las unidades actuales en el inventario, si una unidad sale, desaparece del layout y las unidades en esa columna se acomodan, el layout está hecho en appscript.”

## Evidencia funcional encontrada en el Excel

- Registro diferenciado de ingresos y salidas.
- Identificación de unidad, cliente, almacén, tipo, modelo y fórmula rodante.
- Dimensiones y cálculo de área ocupada.
- Estado nuevo o usado.
- Checklist de implementos, documentación, condición exterior e interior.
- Niveles de combustible y AdBlue.
- Incidencias iniciales y posteriores, con evidencia fotográfica.
- Fotografías de frente, parte posterior, laterales, cabina, guía y tablero.
- Firmas de almacenero y conductor.
- QR y PDF para ingreso y salida.
- Cálculo del inventario mediante cruce de ingresos y salidas.
- Control de variación de área, inventario y clientes.
- Gestión de usuarios y roles.

## Reglas editoriales

- No publicar datos personales, correos, DNI, placas, chasis, rutas, enlaces ni QR reales.
- Usar unidades y clientes ficticios en cualquier demostración.
- No inventar métricas de ahorro, facturación o reducción de reclamos.
- Mostrar el sistema como una solución integral; el layout es su capa visual operativa.
- Mantener continuidad con el mundo 3D isométrico del portafolio principal.
- Los títulos y explicaciones se renderizan como HTML; no se hornean dentro de las imágenes.
